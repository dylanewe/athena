# Explicit knowledge builds (#16)

In **Repositories**, select one to eight registered, present repositories, review their names/paths and the paid-processing disclosure, then check **I authorize paid model processing for this build** and click **Build/refresh knowledge**. Changing repository selection clears that checkbox. Discovery, launch, registration and documentation-hint edits never start a build. Existing provider approvals, pinned role models, folder permissions, secret/environment checks and price gates still apply. Selected repositories guide relevance, not filesystem authorization: relevant references elsewhere in designated folders may be consulted, as disclosed before starting.

Each build is a new ordinary live job/conversation, not a daemon, indexer or separate billing workflow. A bounded access-aware lookup selects retained knowledge per repository before fresh work. A completed, published build receipt with the same knowledge database generation, repository/hints and compatible current checkout can reuse its available current interpretations without model requests. All of a receipt's consulted checkout dependencies must still be compatible, and every retrieved lead must be current. A current claim cannot hide a stale sibling or a later cross-repository claim. Historical stale records remain historical, never revived; when a bounded page still contains them, refresh conservatively investigates rather than guessing that another claim replaced them. Reused knowledge has not become semantically verified simply because its checkout is unchanged. Receipt lookup and knowledge pages are bounded; missing/incomplete leads cause bounded investigation rather than an unsupported claim that the ledger is exhausted.

For new/changed scope, one repository-local assignment per selected repository uses the existing **parallel investigator scheduler**, including its configured concurrency and queued tail. No separate budget or retry policy is introduced: all roles share 50 requests, 15 minutes and the existing durable API-key price gate/ChatGPT plan consent. The main agent synthesizes bounded task results, not child transcripts. Investigators receive their own repository's retained leads and documentation starting directories, prioritize root README variants and those directories, and may inspect arbitrary relevant eligible text/docs and code. No manifest, documentation approval or fixed layout is required. Implementation takes precedence over declarations; recoverable code detail should not be duplicated. Relationship/flow candidates remain optional and use the existing central validator.

Main owns **Knowledge build coverage**, checkpointed in conversation SQLite and shown during/after the job. It records actual source requests/statuses (up to 200), encountered unsupported/withheld inputs and failures (up to 100 each), bounded unresolved questions, reuse and reporting truncation. Listing a path is not reading or understanding every file; unvisited material remains unknown. Reuse links to the original build's coverage and carries its unresolved gaps forward. Coverage is not exhaustive discovery or runtime tracing. Source/report limits and withheld publication yield an explicit partial build; model/request/time limits stop or pause work rather than authorizing automatic continuation.

Completed unexposed candidates enter the existing transactional freshness/reference validator and appear through **Inspect retained knowledge**, **Knowledge** search/details, and any existing map/flow navigation. Changed/deleted assertions remain stale historical evidence unless freshly revalidated. Checkout changes during work prevent incompatible publication. Cancellation/revocation cannot initiate publication; independently committed knowledge is not rolled back. Stop, close and quit cancel the same running/queued tasks. Retry is another explicit job with the original frozen build scope and pinned binding; changed repository identity/hints require selecting and authorizing a new build. Restart marks interrupted work cancelled and never resumes paid generation. Environment-exposed builds retain only the existing safe placeholder, not coverage derived from secrets.

Deterministic coverage: `api-conversations.test.ts` drives the real Pi agents, source policy, supervisor, SQLite and scripted provider through undocumented code, mixed layouts, unsupported inputs, unchanged reuse, stale refresh, cancellation/retry, source truncation and shared request exhaustion. `bridge.test.ts` checks payload/caller restrictions. `workspace.spec.ts` exercises repository selection, explicit paid consent, ordinary utility-process execution, coverage persistence and existing knowledge navigation. No live provider calls are used by tests.
