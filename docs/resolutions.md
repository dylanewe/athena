# Contradictions and user resolutions (#11)

Explicit contradictory claims remain visible together in newly investigated and retrieved-only answers and Knowledge details, with bounded excerpts, paths/line spans, retained revision/content identities and independently checked source freshness. Current implementation evidence takes precedence when explaining implemented behavior. Static interpretation is not runtime observation or independent semantic verification. An undiscovered path or failed search is not proof of absence; intended and historical declarations do not establish current behavior. Neither conflict detection nor resolution invents semantic equivalence between differently worded claims.

## Record an assertion, not a source edit

Open **Knowledge details**, select the relevant claim/evidence versions (up to four), choose **Explain intent**, **Dismiss obsolete declaration** or **Annotate discrepancy**, and save your explanation. This records an explicitly attributed **user assertion**. It does not certify the assertion, change derived claim validation, suppress either side of a conflict, mint an evidence citation, grant permission or instruct an agent. There is no source editing, documentation generation, patch approval, coding action or automatic commit workflow.

Annotations are read-only during active model work or while a sealed conversation is selected. Unsent annotation drafts are memory-only and cleared when the context becomes non-writable. Both initial validation and the final SQLite commit require a main-owned idle, unsealed context and the existing session secret/environment denylist. Workers have no annotation write capability. An exposed/tainted attempt cannot publish annotations or derived knowledge, including seemingly innocuous automatic paraphrases. Normal model retrieval may read bounded annotations as untrusted user assertions; this never changes source, credential, endpoint, cost or provider/role-pinning authority.

## Version bindings and replacement

Each revision binds the annotation to main-owned claim content identities, complete evidence/source version fingerprints and a **derived-ledger generation**. It retains bounded source excerpts and the transitive source provenance necessary to enforce current access after a rebuild. Candidate C/E numbers are never used for reconnection. Inspection compares stored fingerprints against the current claim's complete transitive provenance, including relationships added without changing its content-derived claim ID. Source changes or uncertain freshness show **Requires reconsideration**. User-visible observations are sticky across reverts. Model/tainted reads are read-only and cannot persist new observations. No annotation suppresses future conflicts, even while recorded for unchanged versions.

`state/resolutions.sqlite` (with SQLite WAL/SHM sidecars) is durable user state, separate from rebuildable `state/knowledge.sqlite`. Clearing/replacing knowledge changes its generation. Even exact re-extraction with the same content-derived claim IDs cannot silently reconnect an annotation. **Show all retained annotations, including unconnected versions** makes orphaned annotations inspectable when their source derivations remain accessible. Open the newly extracted claim details, select versions, confirm that you reconsidered the assertion, then choose **Reconsider and reconnect annotation**. This appends a revision rather than overwriting the original bindings; **Inspect original binding** exposes the first revision. Main-owned inspection also supports selecting any retained revision (maximum 32).

Changed/deleted assertions remain separate from new assertions; a user chooses the new binding, not a model or similarity heuristic. Inaccessible derivations withhold the entire annotation, including user text, because it can reveal source-derived material. Reconnection authorizes the existing annotation before carrying its explanation forward, and the explanation's immutable original source-access provenance is checked on every later read/reconnection; rebinding to an accessible source cannot launder revoked source content. Snapshot reads use ordinary Sources policy only, never exceptional environment access. Page, source-check, graph, deadline and serialized-result limits bound annotation inspection; large source envelopes can require fewer selected claims. Retrieval attachments share the original response-wide 32-claim/256-source-identity budget and ten-second deadline, including original annotation provenance and current transitive claim graphs. Standalone annotation inspection has its own shared response-wide context. These opaque contexts live only in main-owned WeakMaps, never renderer/model payloads or persistence; unknown/cloned responses cannot acquire replacement budgets. Attachments cannot create current E evidence. Browsing, annotation writes and reconnection make zero model calls. Source/secret detection remains best effort, not a guarantee; profile storage is private but not encrypted source storage.
