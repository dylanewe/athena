# Reusable investigation knowledge (#8)

Completed, unexposed investigations can retain concise source-backed topics without writing anything into investigated repositories. **Inspect retained knowledge** on an answer opens its records; **Knowledge** in the sidebar inspects them independently. Evidence disclosures include original excerpts, line spans, repository names/aliases, paths, checkout revisions when available and full-file content hashes. **Inspect current file** uses the ordinary source policy and warns about mismatches. After an explicit repository reconnection, old evidence keeps its original path; Sources can inspect the new location.

The detail view separates responsibilities, behavior, domain concepts, decisions and operations. It shows topic summaries, individual claims, provenance, temporal perspective, validation, explicit claim relationships, their originating answers, and inspected-file dependencies. Conflicting and uncertain claims stay visible. The conversation also exposes proposed structured candidates when reconciliation/publication fails; it never claims those candidates became established knowledge.

## Extraction, reconciliation and publication

The existing isolated Pi investigator submits optional `knowledgeCandidates` in `finish_investigation`; there is no extra model request, background paid job or renderer/model write command. The TypeBox schema bounds twelve candidates, each with a local C-number, scope, topic, summary, kind, concise claim, provenance, perspective, evidence IDs and explicit `supports`, `conflicts-with` or `depends-on` references. Existing unstructured candidate notes remain proposals, not executable mutations. The investigator is instructed to distill architecture/domain knowledge rather than copy recoverable implementation details, prefer implementation evidence, preserve intent/decisions separately, and never invent runtime observations.

Athena's central `Knowledge` application service is the sole writer:

1. Require completed extraction and answer, complete dependency coverage, no scope truncation, no environment exposure/sealing, and a live cancellation signal. Apply the same session-level secret/environment denylist as conversation persistence, including the whole outcome before publication.
2. Validate schema (including non-whitespace text), unique local IDs, observed citation references, registered repository scope and all relationship targets. Candidate fields never select tables, SQL, filesystem writes or privileges. Any failure withholds the entire batch.
3. Resolve repository scopes by registered name/alias using the inventory's Unicode-normalized, case-insensitive name contract, not physical basenames, remote URLs or opaque cross-repository IDs. Non-Git text uses its explicitly designated folder scope. Explicit reconnection preserves a name's source identity. Unknown identities are withheld, not guessed or silently merged.
4. Compute an exact content-derived internal record key from scope/topic/summary/claim/provenance/perspective, cited spans and inspected source identities. Candidate order/local evidence IDs do not establish identity. Exact repetitions gain ownership records; differently worded statements, changed source derivations and aliases for different repositories remain distinct. There is no semantic/similarity equivalence merge and no last-writer-wins replacement.
5. Re-read every inspected dependency through the existing read-only Sources boundary, checking both content and current repository ownership. Positive search results carry citations; bounded negative searches also retain inspected-file hashes. List/search operations additionally retain a stable, scope-relative membership/result fingerprint and exact query; repeating those operations detects newly added/deleted eligible files and changed search coverage, not just changes to previously cited files. Truncated coverage withholds publication rather than treating an incomplete search as exhaustive. Uncited inspected files and inspected scopes are dependencies too.
6. Insert claims, indexed source dependencies, answer ownership, explicit relationship edges and relationship ownership in one SQLite transaction. Validate the resulting retained dependency graph, including prior edges on exact repeated claims even if the new submission omits them. Recheck dependencies, cancellation, sealing and secret policy after inserts and immediately before committing. Failures or cancellation roll back the whole batch. Inspections/publications are serialized so another caller cannot inspect uncommitted rows. An answer may still complete if knowledge validation/storage fails; it visibly reports that knowledge was withheld.

Source reads are not an atomic multi-file filesystem snapshot. Freshness is checked at publication/inspection time; hostile concurrent mutation after the last read remains possible, as in the existing citation path. Athena does not execute code, inspect runtime traces, adopt repository instructions, generate proposals/manifests/standardized documentation, or write source edits.

## Provenance is not validation

- **Declared**: a document/comment/configuration declaration, including intended behavior and historical decisions.
- **Statically inferred**: a model interpretation of inspected source, never runtime observation.
- **Supported**: conservatively limited to an intended/historical declaration present verbatim in cited text. This certifies the declaration's presence, **not** its truth as current implementation.
- **Unchecked**: a normalized model interpretation whose schema/references pass; semantic truth is not independently certified. Even plausible implementation summaries retain this label.
- **Conflicting**: explicit conflicting claims are preserved on both sides with traceable links. Implementation evidence takes precedence over declarations; intent/history do not replace current behavior. Complementary/differently worded claims are not automatically declared conflicts.
- **Stale**: an eligible repository checkout or inspected dependency changed, became unavailable, lost folder/source permission, or moved without explicit reconnection. #10 persists sticky invalidation and propagates it along explicit `depends-on` edges. Original record/evidence remains historical; access-permitted stale leads can guide investigation but cannot mint current runtime evidence. Unchanged evidence alone is not proof of unchanged behavior.

[#9 query-selected retrieval](knowledge-retrieval.md) replaces the initial recent-twelve preload. The main agent explicitly searches relevant records, inspects bounded current evidence, or delegates fresh source exploration when indexed knowledge is insufficient. Only query-selected, explicitly labeled **untrusted leads** cross to the isolated investigator, not the whole ledger or conversation transcript. The investigator must inspect fresh sources for new claims; existing record IDs permit explicit relationships. Existing provider/model pins and context/request/cost checks remain authoritative. No model call occurs on knowledge browsing, freshness checking, local indexing, startup or repository discovery.

## Ownership and privacy

`state/knowledge.sqlite` is a separate, rebuildable SQLite database, with WAL/SHM sidecars while open. It contains only derived records/evidence and logical answer ownership; no conversations, credentials, settings or annotations live here. Claims and edges retain originating conversation/message IDs; indexed dependencies use name scope + repository-relative file path + content identity, with separate indexed list/search scope/query fingerprints. Foreign-key cascades permit derived-record deletion/rebuild without touching durable user databases. [#10 checkout freshness](change-invalidation.md) adds local launch/pre-investigation invalidation and an explicit refresh draft workflow. Broader revocation/deletion workflows remain separate. With Athena closed, removing **only** `knowledge.sqlite` and its sidecars resets derived knowledge. It does not delete history. Like ordinary source excerpts, knowledge is not encrypted at rest; keep the application profile private.

[#7 environment safeguards](environment-access.md) are unchanged. An actual-environment-exposed or otherwise sealed/tainted attempt never calls publication and cannot replay its main/investigator context. Neither apparently innocuous paraphrases nor candidates, dependencies, titles, error strings or tool history from that job enter knowledge storage. The central service additionally rejects exposed/incomplete jobs and repeats main-owned policy checks at commit. Local previews remain local-only; known environment values are a memory-only denylist, not future read/send permission. Both ChatGPT and independently pinned API-key roles retain their existing consent and usage/cost gates. There is no extra source permission or paid-work workflow.
