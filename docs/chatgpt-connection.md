# ChatGPT subscription connection

OAuth connection implemented for [#24](https://github.com/dylanewe/athena/issues/24); shared Pi transport and live conversations added in [#25](https://github.com/dylanewe/athena/issues/25). See [live-conversation contract](live-conversations.md). `req.md` is the original LearnHarness reference, not Athena's final storage or account design.

## Protocol sources and live verification

OpenAI's primary documentation was checked on 2026-10-29:

- [Overview](https://developers.openai.com/siwc/token-sharing-open-source): describes ChatGPT plan usage for open-source and locally hosted apps, user/workspace-bound client registrations, stable host IDs, and UUID host IDs as a supported alternative to JWK thumbprints.
- [Registration and sign-in](https://developers.openai.com/siwc/token-sharing-open-source/sign-in): explicitly documents `dynamic_agent_client`, `agent_name_hint`, `ext_agent_host_id`, the six requested scopes, PKCE, nonce, issued callback client IDs, public-client token exchange, and the `127.0.0.1` callback with a variable port but stable path. No client secret or partner API key is required.
- [Models and inference](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference): confirms `GET https://api.openai.com/v1/models` with the `models` / `visibility` / `slug` / `display_name` shape, and `POST https://api.openai.com/v1/responses` with OAuth bearer authorization, `store: false`, `stream: true`, and successful `response.completed` as the terminal requirement.
- [Preview limitations](https://developers.openai.com/siwc/token-sharing-open-source/preview-limitations): prohibits `max_output_tokens`, sampling settings, and several other Responses fields. A normal API-key request shape is not interchangeable with this route.
- [Accounts and sessions](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions): documents refresh rotation, protected credential storage, retaining registration identity after sign-out, revocation, and usage controls. Plan limits can be shared between apps.
- [Errors and recovery](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery): distinguishes identity sign-in from plan permission, describes `prompt=consent` for explicit reconsent, terminal refresh errors, quota failures during streaming, and account/workspace eligibility failures. Athena does not use the newer `force_reconsent` parameter, which requires rollout confirmation.
- [UI guidance](https://developers.openai.com/siwc/ui-ux-guidelines): recommends recognizable ChatGPT sign-in and a link to [ChatGPT Settings → Usage](https://chatgpt.com/settings/usage), including disclosure of plan or enabled-credit usage.
- [OpenID discovery](https://auth.openai.com/.well-known/openid-configuration): confirms the issuer, authorization/token/JWKS/revocation endpoints, PKCE S256 and RS256. Its published scope list only includes the identity/offline scopes; the plan-specific scopes are separately documented in the sign-in guide. That omission alone is not evidence of incompatibility.

These sources establish the protocol contract, not eligibility for every account, workspace, region, or model. After the user signed in, a normal Electron launch successfully unlocked the saved registration and fetched eight models. Two separately authorized fixed-prompt generation attempts initially failed; the diagnostic attempt received HTTP 200 with no Content-Type header, which the client rejected before observing stream events. Missing-header handling now permits bounded SSE parsing while still requiring a valid completed terminal event.

A third, separately authorized live test using the patched production client **completed successfully on `gpt-6.1-sol`**, with reported usage of **13 input tokens, 8 output tokens, and 0 cached input tokens**. No automatic retry, model switch, or billing fallback was used. This verifies live saved-session access, discovery, and generation for that account/model request—not universal entitlement, exact prompt obedience, or live revocation behavior. That live verification used the original narrow fetch/SSE transport, not Pi. The replacement Pi adapter is regression-tested against scripted HTTP, including the missing-header case; it has not been live-verified. Automated tests continue to use fake credentials and scripted provider responses exclusively.

## Approved Athena scope

Local macOS Electron only. There is no web server deployment, hosted account ownership, remote callback relay, or multi-user support. Live conversation and eligible source transmission now use the separately documented #25 path. The system browser must run on the same machine as Athena's loopback listener.

The application name is `Athena`. The fixed connection test has no tools/history; live conversations attach Athena's three read-only source tools and use Pi serialization. The existing DeepSeek connection test, provider permission and dollar gate are unchanged.

**Exactly one saved registration.** This is the user's explicit single-user choice rather than the reference's multi-account model and OpenAI's multi-account UX guidance. Reconnect pins both the saved issued client ID and verified issuer/subject. Email is display metadata, not identity. Disconnect removes all tokens but retains the registration and selected model. To use another account, disconnect and explicitly **Forget disconnected registration** before a new sign-in. Forgetting is local, does not delete the client in ChatGPT, and keeps the installation host ID. There is never an account picker, second saved registration, automatic switch, or API-key fallback.

## Connection and test UX

Open **Model settings → Use your ChatGPT plan**:

1. **Continue with ChatGPT** opens the system browser. The adjacent disclosure authorizes the subsequent model catalog fetch, not generation. The callback page only tells the user to return to Athena; the app reports the verified result.
2. A valid identity without all plan scopes is retained as **Signed in — plan permission missing**. Discovery and generation remain blocked. **Enable ChatGPT plan use** explicitly repeats authorization with the saved client ID, full scopes and `prompt=consent`.
3. Select a discovered model. The ID must exist in the current account catalog; no default is chosen. Catalog labels are rendered as text. The selected ID survives restart, but the catalog does not: **Refresh ChatGPT models** is required after reopening before testing. An unavailable saved model is never replaced automatically.
4. **Test ChatGPT connection** sends only `Reply with exactly: Athena connection OK`, as one user input, with no tools, transcript, repository content or general caller-supplied request options. No output text is returned to the UI; the test confirms a completed exchange, not exact model obedience to the requested wording.
5. A test has a 20-second application deadline and no retries. There is **no output-token cap**, because that field is unsupported. A deadline or cancellation is **not a billing cap** and may not prevent already-incurred usage. Requests use the ChatGPT plan or credits enabled in ChatGPT; DeepSeek's dollar gate does not measure or control this route. Numeric reported input/output/cached-input usage is shown when valid; missing or malformed usage is not fabricated as zero. No dollar estimate is invented.
6. **Disconnect ChatGPT** cancels affected work, clears local tokens, and attempts remote refresh-token revocation. If revocation is unconfirmed, the UI says so and directs the user to ChatGPT settings. It never activates another billing route.

No unattended refresh, polling, automatic generation, or network request occurs at launch. No background-use toggle exists because there is no background subscription work. Refresh happens only when a requested catalog/test/conversation needs access and expiry is within 60 seconds. Conversation Send can refresh an unloaded catalog automatically; the fixed test still requires a loaded catalog. No account or subscription credential is imported from Pi, the shell, another app, or repository files.

Minimizing preserves explicitly requested work. Cancel, renderer failure, close and quit stop login/catalog/generation authority. During shutdown, Athena waits for an already-started, bounded refresh to persist a rotated token before exiting; it never starts generation from that cancelled operation. A queued disconnect still clears local tokens during shutdown. Test outcomes are transient and reset on restart; interrupted tests are not replayed.

## Security and ownership

- Main owns host ID, registration, OAuth state, tokens, protected storage and refresh. Renderer receives only status, email, catalog labels/IDs, selected model and numeric test usage. Shared IPC validates owner window, main frame, exact UI document, operation and payload shape. The usage-settings button opens one application-owned HTTPS URL; there is no arbitrary browser-opening API.
- A fresh 32-byte verifier, state and nonce are created per login. PKCE uses SHA-256/base64url. The ephemeral loopback listener starts before the browser, permits exact origin/Host/path and GET only, rejects duplicate security parameters and wrong state, consumes a matching callback once, and closes on completion/cancel/error/180-second timeout. Callback responses have no-store, a deny-all CSP and no-referrer. OAuth URLs containing ID-token hints are not logged or sent to the renderer.
- Fixed OpenAI endpoints, no redirects, bounded JSON bodies, and 15-second HTTP timeouts. Signing keys are fetched from the fixed JWKS endpoint with `jose`, caching and rotation support. ID tokens require RS256, exact issuer/audience, `sub`/`exp`/`iat`, initial nonce, and correct `azp` when present or when multiple audiences exist. Reconnect/new refresh ID tokens must match the saved subject. Previously verified retained ID tokens need not be unexpired when a refresh omits a replacement.
- A usable token set requires all six scopes, bearer access, a refresh token and finite positive expiry. `sk-` access tokens are rejected. A partially authorized identity may retain validated tokens but has no plan request authority.
- All credential mutations and refreshes are serialized. Rotated credentials commit before becoming request authority, even if cancellation occurred during refresh. A queued disconnect revokes the latest token. Terminal refresh/identity failures invalidate tokens and require reconnect. Temporary network failure does not erase credentials. Storage failure blocks use rather than falling back to plaintext or continuing with unpersisted rotation.
- Main spawns one supervised Electron utility for an explicit test, with empty environment, ignored stdio and only an access token plus selected model. The utility constructs the fixed request itself. The parent validates/sanitizes results and kills the process on completion, crash, timeout or cancellation, including cancellation before spawn. Refresh/ID tokens never enter the worker. Process separation is **not an OS sandbox** against malicious trusted worker code.
- `chatgpt-stream.ts` wraps the direct Pi OpenAI Responses adapter, supplies only the Athena-issued access token, allowlists subscription fields, disables retries, and bounds total response/individual event bytes before SDK parsing. It handles chunked UTF-8/CRLF and only accepts `response.completed` with completed response status. The fixed test ignores answer text; conversations stream text and defer tool execution until verified completion. A missing Content-Type header is tolerated, but an explicitly incompatible media type is rejected; neither HTTP 200 nor an absent header counts as successful inference. Failed/incomplete/error events, premature EOF and interruption are failures. Errors are reduced to application-authored categories; raw provider bodies, tokens and headers are not logged or forwarded.

## Storage and profile lifecycle

`<Electron userData>/state/chatgpt.sqlite` defaults to `~/Library/Application Support/Athena/state/chatgpt.sqlite`. The profile's owner-only state directory contains one encrypted record; the SQLite file is created owner-only (`0600`) before opening. The record contains version, UUID-based `urn:uuid:…` host ID, optional single registration, and optional selected model. All identity and token fields are encrypted together with Electron `safeStorage` using a macOS Keychain-backed key. There is no plaintext JSON credential file.

SQLite uses atomic record replacement, full synchronization, delete journaling and secure deletion; journals contain ciphertext, not plaintext tokens. Malformed records are rejected as a whole. Protected storage must be available to read or write; corruption/decryption/persistence errors lock out credential operations until restart and repair rather than silently resetting the account. The app's existing profile-scoped single-instance lock prevents concurrent application owners. This is not a design for sharing a credential directory between processes or machines.

Host identity is defined per Athena profile. It persists across restarts, disconnect and local registration forgetting. A deliberately separate `--user-data-dir` is a distinct host/profile. Do not copy an active profile to create a second owner.

Credentials are separate from conversation/inventory/source data and never included in model context or renderer bundles. Git ignores the credential database/sidecars and reference JSON/temp filenames. Builds bundle application code only. Backups of the entire state directory include encrypted credentials: protect those backups and do not treat encryption as protection from software already running as the logged-in user. Disconnect deletes tokens logically; encrypted filesystem/backup remnants are not a guarantee of secure media erasure.

## Implementation and tests

| File | Responsibility |
| --- | --- |
| `src/main/chatgpt-protocol.ts` | Fixed OAuth endpoints, loopback callback, token/JWT validation, catalog, revocation |
| `src/main/chatgpt-store.ts` | Strict single-record schema and protected atomic persistence |
| `src/main/chatgpt-settings.ts` | Serialized operations, refresh/cancellation authority, single-registration lifecycle |

| `src/main/chatgpt-process.ts` | Utility supervision and safe result decoding |
| `src/worker/chatgpt-exchange.ts`, `chatgpt.ts` | Fixed generation test using the shared wrapper |
| `src/worker/chatgpt-stream.ts` | Direct Pi Responses serialization/streaming with subscription payload, endpoint, byte bounds, retry and terminal enforcement |
| `src/shared/chatgpt.ts`, `src/renderer/ChatGPTSettings.svelte` | Public status contract and settings UI |

`npm test` runs deterministic service/protocol/worker tests plus real Electron tests. Desktop fixtures replace provider HTTP and system-browser launch, retaining the real loopback server, RSA/JWKS verification, Electron safeStorage API, preload/IPC, and actual utility process. Playwright's Electron launcher enables a mock Keychain: these automated tests exercise ciphertext persistence but do not prove real login-Keychain integration. The separately authorized live check used normal Electron (without that switch) and successfully read the user's protected registration. Never use Playwright's default mock-Keychain launch against a real credential profile. Coverage includes callback attacks, denied consent, identity/scopes, malformed storage, locked storage, cancellation/refresh races, persisted rotation, revocation failure, unavailable selections, completed/interrupted streams, process failure, lifecycle shutdown, cross-window rejection, and no request on restart.
